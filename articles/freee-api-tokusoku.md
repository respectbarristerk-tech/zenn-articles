個人事業主向けに「支払期日を過ぎた未入金を検知して、督促メールの文面を用意するツール」を作りました。

設計段階では素直に作れるつもりでいたのですが、実際にAPIを叩くたびに前提が崩れました。**崩れた5つ**を、なぜ崩れたかとあわせて残しておきます。freee APIを触る人の役に立つはずです。

作ったもの: https://tokusoku.onrender.com

## 崩れた前提① 「未決済」は「未入金」ではない

最初に考えた検知条件はこれでした。

```
type = income AND status = unsettled AND due_date < 今日
```

freee会計の取引(`deals`)には決済状況があるので、「未決済で期日を過ぎたもの」を拾えば未払いだろう、と。

**これが間違いです。**

`status = unsettled` が意味するのは「**入金消込という帳簿処理が済んでいない**」であって、「入金がない」ではありません。ズレはこう生まれます。

1. 銀行同期のラグ(入金してもfreeeに反映されるまで数時間〜1日)
2. 反映されても「自動で経理」の未処理明細に留まり、ユーザーが消込操作をするまで `unsettled` のまま
3. **月末にまとめて消込する運用なら、最大1ヶ月ズレる**

つまり素直に実装すると、**すでに入金してくれた取引先に催促するツール**ができあがります。督促という文脈でこれは事故です。

### 対処

`wallet_txns`(自動で経理の明細)を見ます。

| フィールド | 内容 |
|---|---|
| `status` | **1: 消込待ち** / 2: 消込済み / 3: 無視 / 4: 消込中 / 6: 対象外 |
| `entry_side` | `income` で入金明細に限定 |
| `amount` / `date` | 金額・入金日 |
| `description` | **振込人名義のカナが入る** |

**未決済取引と同額の「消込待ち」入金明細があれば、入金済み・未消込の可能性が高い**と判定して督促を止めます。`description` の振込人名義を `partners.name_kana` と照合すれば精度が上がります。

これが結果的に、このツールで一番重要な機能になりました。

## 崩れた前提② 支払期日で絞り込めないと思っていた

参照したサードパーティSDKのスキーマに、`deals` の日付フィルタが `start_issue_date` / `end_issue_date`(発生日)しかありませんでした。

「支払期日で絞れないなら、未決済を全件取ってクライアント側でフィルタするしかない。1日1回の全件同期と自前DBが要る」── そう設計しました。

**実際に叩いたら `end_due_date` が効きました。**

```
GET /api/1/deals?type=income&status=unsettled&end_due_date=2026-07-26
```

公式のOpenAPIスキーマを確認したら、`start_due_date` / `end_due_date`(支払期日で絞込)が**正式に定義されていました**。SDKが古かっただけです。

全件同期の設計は丸ごと不要になりました。

### ただし副作用がある

**期日フィルタを指定すると、`due_date` が `null` の取引は結果から落ちます。**

期日が入っていない取引は「督促の起点が決まらない」ので別扱いにしたいのですが、フィルタをかけると存在ごと消えます。フィルタなしのクエリを別に投げて差分を取る必要がありました。

> **教訓:** サードパーティSDKのスキーマを仕様書代わりにしない。公式のOpenAPIスキーマ([freee/freee-api-schema](https://github.com/freee/freee-api-schema))を見る。

## 崩れた前提③ 取引先のメールアドレスが1件も入っていない

督促メールを送るので、`partners.email` を宛先に使います。

開発用テスト事業所のデモ取引先を確認したところ、**37社すべてで空**でした。

デモデータではありますが、freeeの取引先登録でメールアドレスが必須でないことの反映です。実ユーザーでも充足率は低いと考えるべきでしょう。

当初は「初回セットアップで全取引先のメールアドレスを入力してもらう」設計にしました。**37社分を初回に入力させる**わけです。現実的ではありません。

### 対処

`mailto:` は**宛先が空でも成立します。**

```
mailto:?subject=...&body=...
```

メールソフトが宛先欄を空で開くので、ユーザーがアドレス帳から選べます。これで充足率0%が致命傷でなくなり、必須フローを丸ごと削れました。

### ついでの落とし穴

freee APIは**未設定を `null` と `""` で混在させて返します。**

- `partners.email` … 未設定は `""`
- `deals.ref_number` … デモデータは `null`、API経由で省略作成すると `""`

片方だけの判定を書くと、必ずどこかで誤動作します。

## 崩れた前提④ 日本語の督促文はmailtoに載らない

「文面を作って `mailto:` でメーラーを開く」という設計にしました。送信基盤を持たずに済み、OAuth審査も不要、到達率も100%です。

実装して文字数を数えたら、こうなりました。

| | 見た目 | URLエンコード後 | 倍率 |
|---|---|---|---|
| 件名 | 32文字 | 172 | 5.4x |
| **本文** | **404文字** | **2,912** | **7.2x** |
| **mailto URL 全体** | | **3,129** | |

日本語1文字はUTF-8で3バイト、パーセントエンコードすると `%E3%81%82` のように**9文字**に膨らみます。

**Windows + Chrome + Outlook の実用上限は約2,000文字。**そして超えたときの挙動が最悪で、**URLが切り詰められるのではなく、メールソフトが起動しません。**ユーザーには「ボタンを押しても何も起きない」としか見えません。

2,000に収めるには本文を247文字まで削る必要がありました。督促文としての丁寧さが犠牲になります。

### 対処その1:本文はクリップボード経由

```
mailto:{宛先}?subject={件名}     ← 211文字。余裕で収まる
本文 → クリップボードにコピー → ユーザーが Ctrl+V で貼り付け
```

### 対処その2:Gmailなら本文も載る

これは後から気づきました。**OSがメールソフトを起動する経路を通らなければ、2,000文字の壁は関係ありません。**

```
https://mail.google.com/mail/?view=cm&fs=1&to=...&su=...&body=...
```

ブラウザでGmailの作成画面を開くだけのURLです。OAuth認可も審査も不要、ただのリンクです。

「Gmailの上限は約4,096文字」という情報を見かけたので実測したところ:

| 本文 | URL長 | 結果 |
|---|---|---|
| 410字 | 3,173 | ✅ 全部入った |
| 442字 | 3,455 | ✅ 全部入った |
| 562字 | 4,526 | ✅ 全部入った |
| 922字 | **7,739** | ✅ 全部入った |

**上限に達しませんでした。**4,096という数字は、少なくとも作成画面URL(`view=cm`)には当てはまりません。

結局、設定で「ブラウザのGmail」と「その他のメールソフト」を選べる形にしました。Gmailなら貼り付け不要です。

> **教訓:** 二次情報の数字を鵜呑みにしない。5分で実測できるなら実測する。

## 崩れた前提⑤ 「使えるかどうか」は審査を受けるまで分からない

freeeアプリストアには「**プラン限定アプリ**」という区分があります。特定機能を持つアプリは、上位プラン契約の事業所にのみ提供が制限されます。

該当リストにこれがありました。

> **②高度な消込機能**(個人: 会計プレミアムプラン限定)
> 前受金管理・**分割入金**・一括で大量に消込など、債権の消込を高度なレベルで行う機能を持つアプリ

このツールは一部入金の残額を表示します。「分割入金」と解釈されると、**個人はプレミアムプラン(月3,316円)契約者限定**になります。想定ターゲットはスターター(月980円)層なので、市場がほぼ消えます。

加えて「**金融サービス**」の定義も広く、「収納代行」「入出金管理」「情報提供・分析等の間接的なサービス」が含まれます。未入金の検知と督促が該当するかは、読んだだけでは判断がつきません。

実装前に確認したくてfreeeに問い合わせたところ、回答はこうでした。

> プラン限定アプリや金融サービスへの該当性につきましては、ご申請いただいたアプリの詳細な仕様や実際の挙動を担当部署にて審査させていただいた後でなければ、判断が難しい状況でございます。

**公開申請するまで分かりません。**そして公開申請には、実利用向け事業所・パブリックアプリ・公開URLで動くアプリ・ヘルプページ・アイコン等が必要です。

つまり **「実現できるか確定してから作り込む」という順序が取れない。**一通り作ってからでないと、致命的リスクの有無が判明しません。

### 逃げ道はあった

freeeアプリには2種類あります。

| | 事業所数 | 審査 | 銀行明細の取得 |
|---|---|---|---|
| **プライベートアプリ** | **5以下** | **不要** | **申請不要** |
| パブリックアプリ | 20以下(公開後は無制限) | 必要 | 申請必要 |

**5事業所までなら、審査も銀行明細取得申請もなしで全機能を動かせます。**しかも開発用テスト事業所はこのカウントに含まれません。

なので今はプライベートアプリのまま、5人に使ってもらって手応えを見る段階にしています。アプリタイプは後から変更できないので、公開するときは別途パブリックアプリを作ることになります。

あと、これも書いておきます。

> 開発用のテスト事業所(無料のご契約)からのお問い合わせにつきましては、原則としてサポート対象外とさせていただいております。

**freee APIについて公式回答が欲しいなら、有料契約の本番事業所が必要**です。

## その他、細かい発見

**`deals` に取引詳細ページのURLはない**
スキーマ全体でURLを返すのは `download_url`(証憑)と `status_url` のみ。「freeeで開く」ボタンを作るなら、取引一覧に飛ばして目印(取引先名・発生日・金額)を併記するしかありません。freee請求書APIには2026年5月に `report_url` が追加されたので、会計側もいずれ来るかもしれません。

**自社の振込先口座は取得できない**
`walletables` が返すのは口座の表示名・残高・同期状態だけで、口座番号も名義もありません。`partners.partner_bank_account_attributes` は**取引先の**口座です。督促文に振込先を載せたいなら、ユーザーに手入力してもらう必要があります。

**`walletables.meta.up_to_date` は当てにならない**
「銀行同期が最新か」のフラグですが、**一度も同期していない銀行口座を作っても `true` のまま**でした。`sync_status` / `last_synced_at` はスキーマに定義されているのに、同期設定のない口座では**返ってきません**。結局、口座ごとの `wallet_txns` の最新日付から自前で鮮度を推定する方式にしました。

**`deal_origin_name` は使えない**
取引の登録元(例: `"手動"`)が返るのですが、**enumが未定義**で取りうる値が文書化されておらず、クエリでの絞り込みもできません。API経由で作った取引も `"手動"` になるので、判別材料になりません。

## できたもの

- Python + Flask、Render(無料)+ Supabase(無料)で**月額0円**
- freee APIへは**参照(GET)のみ**。書き込み権限を持たない
- 取引先の情報はDBに保存せず、表示のたびにfreeeから取得
- トークンと督促文は暗号化して保存

権限を参照のみにしたのは、プラン限定アプリ対策でもあります。**書き込み権限を持たないアプリが消込を行うのは技術的に不可能**なので、審査でそれを示せます。自己申告より強い論拠になるはずです。

## 使ってくれる方を探しています

正直に書きます。**私は会社員で、自分の請求書がありません。**未払いに困った当事者ではないので、このツールが本当に役に立つのか、自分では確かめられません。

デモデータでの動作は確認しましたが、実際の取引データで何が起きるかは分かっていません。とくに:

- そもそも掛売上(未決済取引)を登録している人がどれくらいいるのか
- 取引先のメールアドレスは実際どれくらい埋まっているのか
- 「入金済みなのに未消込」の取引は本当に存在するのか

**プライベートアプリの枠は5事業所です。**freee会計で掛売上を登録している個人事業主の方で、試してもよいという方がいらっしゃれば、ご連絡いただけると助かります。

督促を実際に送らなくても構いません。**連携して画面を見て、何が表示されたかを教えていただくだけ**で、上の3つはほぼ分かります。

- 権限は**参照のみ**です。freeeの帳簿に書き込むことはできません
- 取引先の情報はサーバーに保存していません
- 設定画面からいつでも連携解除とデータ削除ができます
