## 1. なぜ「既存ツールとは別で」課金を作るのか

有料化ロードマップを引くにあたり、最も重視したのは「**審査を通した本番環境を絶対に壊さない**」ことでした。

すでにfreeeの審査を通過し、RenderとSupabaseで稼働しているWebアプリにいきなりStripe決済や規約変更を直接ねじ込むと、以下のリスクが生じます。

- 審査済みコードに予期せぬバグが混入して既存機能が動かなくなる
- 決済のテストをするたびに本番デプロイが走り、審査時の挙動とズレる
- freeeの掲載内容変更には再申請と審査日数がかかるため、価格の試行錯誤ができない

そこで、「**本番Webツールには一切手を触れず、独立した決済・ライセンス検証モジュールを外付けで作る**」（`課金システム/`）という構造を採用しました。

```
【本番環境（審査通過済み）】      【独立課金システム（新規開発・検証）】
  督促ツール_web                  課金システム/
    ├── app.py                      ├── billing_app.py   (Stripe Checkout/Webhook)
    └── logic.py                    ├── activate_user.py (手動集金CLI)
          │                                │
          └─────────[ Supabase DB ]────────┘
                   (users テーブルで安全に共有)
```

こうしておけば、既存ツール側には後から「`paid_until` が未来なら有料とみなす」という数行の安全な判定（パッチ）を差し込むだけで済みます。

## 3. 最も効いた「絶対ルール」：プロンプトの事前確認

マルチエージェントを動かす上で、ひとつだけ**絶対に譲れない運用ルール**を設けました。

> **「Geminiが話を整理してプロンプトに変換したら、必ず人間に提示して確認を取り、承認を得てから各エージェントに指示を出す」**

AI同士を勝手に会話させると、小さな誤解が連鎖してとんでもない方向に進むことがあります。
賢いGeminiに「各AIに何をどう指示するか」を日本語で書かせ、**私がその指示内容（作戦）を読んで「OK」を出してから実行する**。

この「Human-in-the-loop」を挟んだことで、作業の脱線が完全にゼロになりました。

## 4. 総点検で浮き彫りになった「技術と法律の穴」

各エージェントから上がってきた成果物を総点検した際、非常に実践的な学びがいくつもありました。

### ① 法務面：景品表示法の二重価格表示（ローカルAIの指摘）
当初、「通常年額3,000円 → 先着50名限定 年額1,500円（50%オフ）」という募集文面を作ろうとしていました。
しかし、ローカルAIのリーガルレビューから以下の指摘が入りました。

> **指摘:** 「まだ3,000円で販売した実績がない新サービスで『通常3,000円から半額』と書くと、景品表示法上の不当な二重価格表示（有利誤認）に抵触するリスクがある。」

これは盲点でした。すぐに「Founding Users 特別価格：年額1,500円（将来の一般提供予定価格3,000円）」という表現に修正しました。

### ② 法務面：特商法第11条但書の住所開示特例
個人事業主が自宅住所を非公開にするための「請求があれば遅滞なく開示する」表記ですが、単にそう書くだけでは不十分で、「**開示請求を受け付けるメールアドレス**」と「**電磁的記録（メール等）で遅滞なく提供する旨**」を明確に記載する必要があることも判明し、テンプレートに反映しました。

### ③ 技術面：Pythonのタイムゾーン比較エラー（Gemini / Claude検証）
手動集金CLI（`activate_user.py`）で、DBの `paid_until`（TIMESTAMPTZ）と現在時刻（`datetime.now(timezone.utc)`）を比較して有効期限を延長する際、タイムゾーンなし（naive）とタイムゾーン付き（aware）が混ざると `TypeError` でクラッシュするリスクがありました。

```python
def make_aware(dt):
    """datetime を確実に UTC aware に正規化する"""
    if dt is None:
        return None
    if dt.tzinfo is None:
        return dt.replace(tzinfo=timezone.utc)
    return dt.astimezone(timezone.utc)
```
このように確実にUTC awareへ正規化する関数を挟むことで、例外クラッシュを未然に防ぎました。
