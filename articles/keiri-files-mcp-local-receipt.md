PCに溜まったレシートや請求書（PDF・画像）を、AIに読ませて
「規則的なファイル名にそろえる」「台帳CSVに追記する」「あとで検索する」
までを任せるためのローカルMCPサーバー **keiri-files-mcp** を作りました。

https://github.com/respectbarristerk-tech/keiri-files-mcp

MITライセンスで、Claude Desktop 向けの `.mcpb` も用意しています。
この記事では、作るときに決めたことと、実機で試して変えたことを書きます。

:::message
テストはすべて架空のレシート・請求書で行いました。電子帳簿保存法の要件を満たすことは保証しません。「ファイル名と一覧表を整える補助」です。
:::

## 何をするツールか

| ツール | 内容 | 書き込み |
|---|---|---|
| `scan_folder` | 許可フォルダ内の PDF/JPG/PNG/HEIC を一覧（台帳登録済みかも表示） | なし |
| `read_file` | 画像はそのまま、PDFは埋め込みテキストをAIに渡す | なし |
| `propose_names` | 日付・取引先・金額・書類種別から命名案と形式エラーを返す | なし |
| `apply_renames` | 承認された案だけを実行（既定はコピー、上書きなし） | あり |
| `ledger_append` | 台帳CSV（Excelでそのまま開けるUTF-8 BOM付き）へ追記 | 追記のみ |
| `search_ledger` | 日付・金額・取引先で検索 | なし |

命名は `YYYYMMDD_取引先_金額_書類種別.拡張子` です。

## 決めたこと1: OCRはツールに入れない

読み取りは利用者のAI（Claude など）に任せ、ツールは「ファイルを渡す」「決まった形式で書く」だけにしました。

- 画像の読み取りは、今のマルチモーダルなAIの方が得意
- OCRエンジンを同梱すると依存が増え、導入とレビューが重くなる
- ツールの責任範囲が狭いほど、利用者のAIに「このツールは安全か」を読ませやすい

## 決めたこと2: できることを最初から狭くする

利用者のPCで動く道具なので、「できないこと」を先に決めました。

- 外部通信なし、削除なし、子プロセスの実行なし
- 許可フォルダの外は読み書きしない。パスは実パスに解決してから判定し、`../` やシンボリックリンクでの脱出も拒否
- 書き込みは「承認された命名案の実行」と「台帳への追記」だけ。既定はコピーで、元ファイルは残る
- 書き込みを伴うツールには MCP の annotations（`readOnlyHint` / `destructiveHint`）を付け、クライアントの承認画面に任せる

README の先頭には、利用者が自分のAIに貼る「導入前チェック」のプロンプトを置きました。

```text
このリポジトリのREADMEとsrcを読んで、外部通信・削除・許可フォルダ外アクセスがないか要約してください。
問題なければ、私の環境に合う導入手順を示し、私の承認を得てから実行してください。
```

## 決めたこと3: 命名は「案」と「実行」を分ける

`propose_names` は何も変更せず、命名案と `plan_id` を返すだけです。
`apply_renames` はその `plan_id` の案しか実行できません。

AIが読み間違えた値がそのままファイル名になるのを防ぐため、間に人の確認を挟む形にしています。
同じ名前がぶつかったときは `_2`、`_3` を付け、ファイル名に使えない文字は置き換えます。
Windows の予約名（`CON` など）は先頭に `_` を付けます。

## 実機で試して変えたこと

Windows の Claude Desktop に `.mcpb` を入れて、架空の証憑10件で試しました。

### v0.1: AIがファイルを開けなかった

一覧・命名・コピー・台帳・検索は一度で通りました。
ところが、通常のチャットでは **AIがレシートの中身を見る手段がありません** でした。
「読み取りはAIの役割」と決めたのに、そのAIにファイルを渡す道がなかったわけです。

→ v0.2 で `read_file` を追加しました。許可フォルダ内の画像を MCP の image コンテンツで返し、PDF は依存を増やさずに埋め込みテキストを取り出して返します（取り出せない場合はPDFそのものを resource で返します）。

追加後の再テストでは、画像6件・PDF4件の日付・取引先・金額・書類種別・登録番号を10件とも正しく読み取れました（架空の、読みやすい証憑での結果です）。

### v0.3: 見積書が「支払い」として台帳に載った

見積書も他の書類と同じように台帳へ1行追加されていました。見積書は支払いの記録ではありません。

→ 見積書は既定で台帳に入れず、理由を返すようにしました（必要なら `include_quotes: true`）。
納品書は請求書と二重計上になりうるので、追記はしつつ注意を返します。

### v0.3: 同じレシートを2回撮るとすり抜けた

二重登録はファイル名でしか見ていなかったため、同じレシートを2回撮った写真は別物として通りました。

→ 日付・取引先・金額が同じものは「重複の可能性」として警告するようにしました。止めるかどうかは利用者とAIが決めます。今は完全一致だけで、「(株)」と「株式会社」の違いは見逃します。

## 導入

Claude Desktop なら、Releases の `.mcpb` を開いて許可フォルダを選ぶだけです。
Claude Code / Codex / Gemini CLI の設定例は README にありますが、これらは実機では未確認です。

## 制限

- 約3.7MBを超える画像は読めません（縮小は入れていません）。スマホの写真は縮小してから
- HEIC は `read_file` では読めません。JPGに変換してください
- PDF の文字の取り出しは簡易な実装です。実際の請求書PDFでの精度は未確認です
- 税務判断（勘定科目、経費になるか）はしません

## まとめ

- 読み取りはAIに任せ、ファイル操作は狭く固いツールにする
- 「案」と「実行」を分けて、人の確認を挟む
- 実機で試すと、設計の前提の抜け（AIがファイルを開けない）がすぐ見つかる

不具合や要望は GitHub の Issues へどうぞ。
